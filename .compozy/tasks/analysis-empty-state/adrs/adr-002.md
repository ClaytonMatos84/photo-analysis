# ADR-002: Defer photo preview until the analysis result arrives

## Status

Accepted

## Date

2026-07-21

## Context

On the photo analysis page, `PhotoDisplay` currently renders the selected image preview as soon as a file is chosen (`v-if="imageFile"` in `PhotoAnalysisView`), before the user submits it for analysis and before any result exists. This differs from the ad and video pages, where a preview also appears pre-submission (image URL preview, video embed), but the user has now asked to change the photo page's behavior specifically: the photo preview should appear together with the analysis result, not before.

Combined with ADR-001, this raises a question: should the new empty state disappear the moment a file is selected (matching the ad/video pattern) or stay visible until the result returns? The user confirmed the photo flow should show the empty state until the result exists, then swap directly to the image preview shown alongside the result — removing the immediate pre-submission preview.

## Decision

Change `PhotoAnalysisView` so `PhotoDisplay` only renders once `analysisResult` is populated (i.e., gate it on the presence of a result, not merely on `imageFile`). The new `AnalysisEmptyState` (ADR-001) stays visible for the entire pre-result window on this page, including while the file is selected and while the analysis is in progress, then is replaced by the image preview + dashboard together when the result arrives.

This intentionally makes the photo page's preview timing diverge from the ad and video pages, where the preview (image URL preview, video embed) legitimately appears before the result because it previews the *input* the user is about to submit, not the *output*. The empty state's visibility rule per page is:

- Photo page: empty state visible until `analysisResult` exists; then image preview + dashboard replace it.
- Ad page: empty state visible until the image URL preview or the result appears (whichever comes first); the empty state disappears as soon as a valid preview is shown.
- Video page: empty state visible until the result exists; the video embed only renders together with the result (no separate pre-result preview exists on this page today), so the empty state's visibility mirrors the photo page's rule.

## Alternatives Considered

### Alternative 1: Keep the immediate photo preview and place the empty state below it

- **Description**: Leave `PhotoDisplay` rendering on file selection; show the new empty state only in the remaining space until the result arrives.
- **Pros**: No behavior change to the existing preview; smaller diff.
- **Cons**: Contradicts the user's explicit request; also produces a layout where the empty state's "step 1: submit" content awkwardly coexists with an already-visible preview.
- **Why rejected**: The user explicitly asked to change this behavior.

### Alternative 2: Show empty state and preview side by side after file selection

- **Description**: Keep the preview on selection, but shrink the empty state to a smaller companion panel next to it.
- **Pros**: Preserves some early visual feedback of the selected file.
- **Cons**: Adds a new intermediate layout state to design and maintain, increasing scope beyond what was requested.
- **Why rejected**: The user's answer was direct and unconditional: preview should only appear with the result.

## Consequences

### Positive

- Photo page behavior now matches the user's explicit intent: no premature preview, informative empty state fills the space until real value (the result) is ready.
- Simplifies the pre-result UI on the photo page to a single, consistent empty-state view.

### Negative

- Users lose the earlier confirmation that "the right file was selected" via the immediate preview; they only see the file preview once analysis completes.

### Risks

- If a user selects the wrong file, they will not notice until the result returns (up to ~120s per the API timeout constraint). Mitigation: out of scope for this change; documented as a known trade-off accepted by the user.
